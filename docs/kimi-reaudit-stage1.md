## Q2 regression review (as requested)

- **Partial unique indexes (050):** sound. `ON CONFLICT (mention_key) WHERE status IN (...)` arbiter predicates exactly match the index predicates (`src/db.ts:194-203,271-283` vs `050:8-15`); concurrent inserts collapse to one; finished/failed rows retained for audit. Caveats: R-06, R-07.
- **Ingest re-delivery:** correct and idempotent (`enqueueIfIdle` TOCTOU is closed by the partial index; `handled_mentions` claim makes re-processing safe). **But** it interacts badly with the un-reaped `claimed` state — this is R-01.
- **Publisher `skipped/failed`-only skip:** correct; the HAPPY-path (`processing` → PUT) and duplicate-suppression (`published` → done) orderings are right (`src/publish.ts:38-58`).
- **Stale `publishing` reclaim + `failExhaustedPublishes`:** sound. Tick order (fail-exhausted *then* claim) prevents an exhausted stale row being reclaimed; fresh claims by another process are never failed underneath (`updated_at < now()-staleMs` guard); attempts increment on claim so a repeatedly-crashing row terminates.
- **Bounded `listPosts`:** correct cursor pagination with loop-guard; `isDirNotFound` correctly scopes the first-publish exception; fail-closed otherwise. Residuals in R-04.
- **Advisory-lock migrator:** sound — session lock on a dedicated client held for the whole run (`src/infrastructure/database/migrator.ts:52-66`), released on error or connection death; `--role all` parent migrates once, children get `JEB_SKIP_MIGRATIONS=1` (`src/main.ts:16-24`), contract adapter parent migrates (`src/contract-adapter.ts:26-27`), standalone roles still self-migrate under the lock. The post-migration `ALTER TABLE … IF NOT EXISTS` in `Store.migrate` runs outside the lock but is concurrency-safe.
- **`isNotRegistered` accepting PkarrError "No HTTPS endpoints found":** **acceptable.** Triggering signup requires *all* of: a PkarrError (name or "pkarr operation failed" text), the specific phrase, and the string `_pubky.${botPk}` — our *own* key, which an attacker does not control and can only obtain by echoing our request path (i.e., an already-hostile relay/homeserver). Transient errors are pre-filtered (`src/auth-error.ts:19-22,36-43`). Critically, the signup **target** is `resolveHomeserver(opts.homeserverPk)` — the operator-configured homeserver, never attacker-influenced (`src/homeserver.ts:36-41`) — and the token is single-use. Worst case: token burn / an intended-anyway session on the configured homeserver. No key-boundary crossing. Only nit: R-05 (log it).
