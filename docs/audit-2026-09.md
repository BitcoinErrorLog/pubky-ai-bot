### Trace (`PUBKY_BOT_MNEMONIC`)

1. **Env** `PUBKY_BOT_MNEMONIC` substituted in `config/default.json` (`botMnemonic`: `${PUBKY_BOT_MNEMONIC}`) via `src/config/index.ts` `resolveEnvVars` (fallback `''`, then required-var error at lines 115–141).
2. **Zod** `src/types/config.ts:26` `botMnemonic: z.string().min(1)`.
3. **`appConfig.pubky.botMnemonic`** read in `src/services/pubky.ts` `initializeKeypair()` **153**.
4. **BIP39** `validateMnemonic` / `mnemonicToSeedSync` **165–172**; first 32 seed bytes **173**.
5. **`Keypair.fromSecretKey(seedBytes)`** stored on **`this.keypair`** **176**.

`keypair` and `session` are **private**. There is **no getter**. Reachable only through `PubkyService` methods:

| Module | How it touches session / secret |
|---|---|
| `src/config/index.ts`, `src/types/config.ts`, `config/*.json` | Hold mnemonic string in process config object |

## 6. Nexus API compatibility (`pubky.ts` / `poller.ts`)

Facts used: Nexus is **public (no auth)**; notifications have **no type query filter**; pagination is **`start`/`end` timestamps**, not integer `offset`; mention body is `{ type: "mention", mentioned_by, post_uri }`.

| Assumption | Loc | Verdict | Notes |
|---|---|---|---|
| `GET /v0/user/{pk}/notifications` | `pubky.ts:290–292` | **OK** | Path shape is current. |
| `type=mentioned_by` query | `pubky.ts:294` | **WRONG** | No type filter. Client must filter `body.type === "mention"`. Query type `mentioned_by` is not the body type. |
| Integer `offset` | `pubky.ts:270,296–297` | **WRONG** | Must use `start`/`end` timestamps. |
| `limit` query | `pubky.ts:295` | **OK** | Still used with time windows (confirm against live Nexus). |
| HTTP Basic Auth for Nexus | `pubky.ts:310–315,477–481` | **WRONG** | Public API; auth is dead weight and a secret leak if used. |
| Comment “requires authentication” / `keypair` required to fetch | `pubky.ts:242,275–276` | **WRONG** | Only the bot **public key** is needed in the URL. Session is for homeserver writes. |
| Parse `body.type === 'mention'` + `post_uri` + `mentioned_by` | `pubky.ts:353–355` | **OK** | Matches stated mention body. |
| Also parse `type === 'reply'` | `pubky.ts:356–358` | **DEAD** (for mention bot) / **WRONG** if mixed into mention pipeline | Unfiltered endpoint will return follows, replies, etc. Treating replies as mentions is extra work / noise. |
| Fallback `body.uri` / `body.author` | `pubky.ts:360–362` | **DEAD** | Not the current mention schema. |
| `indexed_at` / `timestamp` on notification | `pubky.ts:411–421` | **OK** if Nexus still sends them; else poller time-window breaks. |
| Post details `/v0/post/{author}/{id}/details` | `pubky.ts:462` | **OK** (not contradicted by given facts; still used for `indexed_at`) |
| Homeserver `publicStorage.getJson(postUri)` | `pubky.ts:522` | **OK** (SDK, not Nexus) | Independent of Nexus pagination. |
| Poller DB `last_offset` integer | `poller.ts:62,152,222,288–327`, migration `002_polling_state.sql` | **WRONG** | Must persist last `indexed_at` / cursor timestamps. |
| Advance cursor by `notificationCount` | `poller.ts:166–167,217–218` | **WRONG** | Offset arithmetic does not match time pagination; comment already notes Nexus may ignore offset. |
| Empty page ⇒ done | `poller.ts:157–159` | **OK** | Still valid if `end` window is empty. |
| Dedup via DB + idempotency | `poller.ts:161,429` | **OK** | Needed even more without a type filter. |
| “Nexus overlapping pages” | `poller.ts:606` | **OK** (workaround) | Symptom of wrong pagination, not a real offset API. |

### Findings

| ID | Severity | Finding |
|---|---|---|
| N1 | Critical | Mentions poller cannot page staging Nexus correctly (`offset` + `type=mentioned_by`). |
| N2 | High | Unfiltered notifications will mix non-mention types unless filtered in-process. |
| N3 | Medium | Basic Auth on public Nexus is unused and logs the username. |
