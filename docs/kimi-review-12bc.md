## Per-surface notes

**1. Web search (src/web/**, http.ts**)** — Attacker text can steer the *query* (that's the feature), but the model's context contains only public Pubky posts, so the query channel carries no confidential data; query is zod-capped at 400 chars and only its SHA-256 is stored. Provider responses: Brave rows are field-validated (`^https?://` URLs only); Moonshot summary is shape-checked then both providers' output passes through `wrap()` → `screenToolResult` (10k char cap + injection sanitize) before re-entering the prompt. No URL fetch beyond the two endpoints — Moonshot search runs server-side, Brave result URLs are never fetched, and `redirect: "error"` in `fetchJsonWith` prevents a 302 from carrying the `Authorization`/`X-Subscription-Token` headers to a third party. Kill switch: `web` added to `SwitchName`, gated env→global→store before every call, and per-mention cap is fail-inclusive (good — no retry storm; failing provider burns the 2/mention cap, daily ceiling is ok-only but bounded by mention rate limits). No secrets in logs (hash only; public error payload is a constant string).

**2. Reply self-tags (reply-tags.ts, publish.ts, migration 071)** — The hard rule holds: `parsePostUri` strict-regexes the URI and `putReplyTags` refuses any author ≠ `transport.botPk` *before any PUT*; `reply_uri` comes from the publisher's own publish result, not user input. Kill switch (`replies`/`global`/env, plus `JEB_SELF_TAGS=0`) is checked both before claiming *and* re-checked immediately before the PUTs; `TagsBlockedError` never consumes an attempt. Retries bounded at 3, idempotent by spec (tag id = hash(uri+label)), failures isolated from the reply publish (warn-log only). Only gap is D7 (vocab not re-validated at the boundary) — non-blocking.

**3. Knowledge ingestion** — Git: `execFile` arg-array (no shell), URL regex-pinned to `https://github.com/owner/repo`, `--` separator before url/dir, shallow+blob:none+sparse, 60 s timeout, 200 MB post-checkout cap, temp dir under `os.tmpdir()` with cleanup on throw, `walkDir` skips `.git` and symlinks (Dirent `isFile()` is false for links → no symlink escape into the corpus). Confidentiality gate covers crawled/collected docs (path + content `evaluateGate` in `ingestPreparedDocs`), `suspect_injection` flag is set for the new kinds and the pre-existing retrieval down-rank applies; tool output is additionally screened at answer time. Crawler: manual redirects with same-host + same-scheme enforcement (no https→http downgrade), 5-hop cap, robots honored, per-page 2 MB, 60-page cap, `allow_paths` globs; failures skip the page. Gaps: D1 (collection item cap), D2 (post-hoc byte cap), D3 (env inheritance). SSRF surface is operator-configured origins only; no DNS/IP pinning, acceptable for that trust level.

**4. Scout** — `rank_users`: metric/order are zod enums mapped through a fixed `Record` for the ORDER BY expression, `since`/`until`/`limit` are bound parameters, LIMIT double-clamped (`lim()` ≤ `scoutLimitMax` ≤ 50, template `min(50, max(1,…))`). No injection. Single-person profiling: no user filter exists — it returns a top-50 leaderboard of public aggregate counts; a narrow `time_range` can spotlight whoever tops a metric in a window, but that's public graph data, and answers remain bound by the "claims, not facts" system rules. Tool-call logging records name/ms/ok/mention_key only — no params/cypher. Retry-storm: bounded per mention by `toolMaxSteps=6`; D4 covers the outage-amplification concern. Non-blocking.

**5. Latency / roles** — Key boundary intact: `configFromProcessEnv` still substitutes a dummy key when `requireSecret` is false, so `ingest-knowledge` and `reason` never load real key material into config; `reason` keeps `assertNoKeyMaterial()`; `runAll` still strips env for children. `JEB_SKIP_MIGRATIONS` only gates the migrator (same advisory-lock migrator as before). Warm-up failure degrades to a warn + `KnowledgeUnavailableError` tool payload, never a crash. ORT threads capped (≤2 intra-op, wasm=1, sequential); production sets `local_files_only` so no runtime model download (supply chain moved to docker build, unpinned HF fetch at build time — informational). D3 is the only boundary-adjacent note.

## Verdict

**FIX-FIRST** — blocking: **D1** (one-line item cap + skip-instead-of-throw in `pubky-collection.ts`; the source is enabled in `sources.yaml` today and an over-large or hijacked collection hangs/kills the ingest role).

Non-blocking follow-ups before or shortly after enable: D2, D3, D4, D5, D8; D6/D7 are hardening hygiene. Web search, self-tags, Scout `rank_users`, and the latency/role changes are otherwise sound to ship as designed.
